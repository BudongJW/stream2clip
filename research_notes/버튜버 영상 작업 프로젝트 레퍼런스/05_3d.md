# 3D VTuber 생태계 및 외부 프로젝트 (VRM, 모션 캡처, 3D 아바타 제작·애니메이션)

> 조사 기준일: 2026-11-18. GitHub 스타 수와 마지막 push 날짜는 ungh.cc의 GitHub API 미러에서 2026-11-18에 조회했다. 라이선스는 shields.io와 저장소 LICENSE 파일(jsDelivr 경유)로 확인했다. npm 버전은 registry.npmjs.org에서 조회했다. 표기 형식은 "★스타 / 라이선스 / 마지막 push"이다.

## 1. VRM 표준과 SDK: VRM 1.0, VRMA, 라이선스 메타데이터, UniVRM, three-vrm, Blender·Godot·Unreal 지원

### Takeaway
VRM 1.0(glTF 기반)과 VRMA(VRM Animation, `.vrma`)는 모두 정식 스펙이다. 주요 엔진 구현 다섯 가지(Unity, three.js, Blender, Godot, Unreal)는 모두 MIT 라이선스이고 2026년에도 활발히 유지보수된다. stream2clip에 특히 중요한 점은 VRM 1.0 메타에 기계가 읽을 수 있는 사용 허가 필드(`commercialUsage`, `allowRedistribution`, `modification`, 폭력·성적·정치 표현 허용 여부 등)가 있다는 것이다. 덕분에 클립을 렌더링하기 전에 아바타 사용 권한을 자동으로 검사할 수 있다.

### Cited Findings
- **VRM 스펙 저장소**: vrm-c/vrm-specification. ★348 / GitHub 기준 라이선스 미지정 / 2026-10-02. — [GitHub](https://github.com/vrm-c/vrm-specification)
- **VRM 1.0 메타(라이선스) 필드** (`VRMC_vrm` meta):
  - 필수 필드: `name`, `authors`(1개 이상), `licenseUrl`(VRM 1.0은 `https://vrm.dev/licenses/1.0/`).
  - `avatarPermission`: `onlyAuthor`(기본값) / `onlySeparatelyLicensedPerson` / `everyone`.
  - `commercialUsage`: `personalNonProfit`(기본값) / `personalProfit` / `corporation`.
  - `creditNotation`: `required`(기본값) / `unnecessary`.
  - `modification`: `prohibited`(기본값) / `allowModification` / `allowModificationRedistribution`.
  - 기본값이 모두 `false`인 boolean 필드: `allowExcessivelyViolentUsage`, `allowExcessivelySexualUsage`, `allowPoliticalOrReligiousUsage`, `allowAntisocialOrHateUsage`, `allowRedistribution`.
  - 그 밖의 선택 필드: `thirdPartyLicenses`, `otherLicenseUrl`, `copyrightInformation`, `contactInformation`, `references`, `thumbnailImage`.
  - — [vrm-specification meta.md](https://raw.githubusercontent.com/vrm-c/vrm-specification/master/specification/VRMC_vrm-1.0/meta.md)
- vrm.dev의 영문 VRM1 meta 페이지는 본문이 "TODO" 상태다. 실제 정의는 스펙 저장소에만 있다. — [vrm.dev meta](https://vrm.dev/en/vrm1/meta/)
- **VRMA (VRM Animation)**:
  - glTF animation에 `VRMC_vrm_animation` 확장을 붙인 형식이고, 권장 확장자는 `.vrma`다.
  - 휴머노이드 본 회전, 표정(preset·custom expression) 가중치, lookAt(시선)을 담는다.
  - "같은 VRMA 파일을 어떤 VRM에도 적용 가능"하다. 리타깃은 받는 쪽 구현이 처리한다.
  - 지원 도구로 UniVRM, @pixiv/three-vrm, VRM Add-on for Blender, bvh2vrma, VRoid Hub, VMagicMirror, VRM Posing Desktop, AnimationClipToVrmaSample 등이 나열돼 있다.
  - draft 버전만 지원하는 앱은 정식 버전 파일에서 다르게 동작할 수 있다고 경고한다.
  - — [vrm.dev VRMA](https://vrm.dev/en/vrma/)
- **UniVRM** (Unity): ★3,424 / MIT / 2026-10-19. — [GitHub](https://github.com/vrm-c/UniVRM)
- **three-vrm** (three.js): ★2,295 / MIT / 2026-10-22. npm `@pixiv/three-vrm`과 `@pixiv/three-vrm-animation`은 모두 3.5.5(2026-07-09 배포, MIT)다. — [GitHub](https://github.com/pixiv/three-vrm), [npm](https://registry.npmjs.org/@pixiv/three-vrm)
- **VRM Add-on for Blender** (saturday06): ★1,741 / MIT / 2026-11-14. 저장소 설명은 "VRM Importer, Exporter and Utilities for Blender 2.93 to 5.3"이다. — [GitHub](https://github.com/saturday06/VRM-Addon-for-Blender), [사이트](https://vrm-addon-for-blender.info/)
- **godot-vrm** (V-Sekai): ★483 / MIT(LICENSE 파일 기준. 샘플 .vrm 모델은 별도 라이선스) / 2026-07-08. Godot 4.1+를 지원하고 MToon 셰이더를 포함한다. — [GitHub](https://github.com/V-Sekai/godot-vrm), [LICENSE](https://cdn.jsdelivr.net/gh/V-Sekai/godot-vrm@master/LICENSE)
- **VRM4U** (Unreal): ★2,015 / MIT(LICENSE 파일 기준. GitHub UI에서는 식별 불가로 표시됨) / 2026-11-10. 저장소 설명은 "Runtime VRM loader for UnrealEngine5"다. — [GitHub](https://github.com/ruyo/VRM4U), [LICENSE](https://cdn.jsdelivr.net/gh/ruyo/VRM4U@master/LICENSE)
- **bvh2vrma** (vrm-c 공식 웹 도구, BVH를 VRMA로 변환): ★87 / MIT / 마지막 push 2024-07-25이고 이후 정체돼 있다. — [GitHub](https://github.com/vrm-c/bvh2vrma), [웹앱](https://vrm-c.github.io/bvh2vrma/)
- **VRoid Hub API**:
  - OAuth 2.0을 쓴다. 개발자 등록을 하고 앱(ClientID/Secret)을 발급받아야 한다.
  - 요청에 `X-Api-Version` 헤더가 필요하다(현재 버전 11).
  - VRM 다운로드 절차: download license를 발급받은 뒤 download 엔드포인트를 호출하면 S3 presigned URL로 리다이렉트된다.
  - Unity용 VRoid SDK가 있고, 업로드 SDK는 별도로 신청해야 한다.
  - — [VRoid Developer API](https://developer.vroid.com/en/api), [OAuth API](https://developer.vroid.com/api/oauth-api.html), [VRoid SDK](https://developer.vroid.com/en/sdk/)

### Inferences
- stream2clip에서 3D 아바타를 렌더링한다면 **three-vrm + three-vrm-animation**(웹/Node)이나 **VRM Add-on for Blender**(Blender CLI 배치 렌더)가 가장 가볍고 라이선스도 깨끗한 선택지다(둘 다 MIT).
- VRM 파일을 받으면 meta 필드를 읽어 다음 경우에 경고하거나 차단하는 기능을 넣을 수 있다:
  - `commercialUsage == personalNonProfit`인데 수익화 채널에서 쓰는 경우
  - `avatarPermission == onlyAuthor`인데 소유자가 아닌 사용자가 렌더링하는 경우
  - `creditNotation == required`일 때 크레딧을 자동으로 넣어야 하는 경우
  - 이 기능은 차별화 요소가 될 수 있다.
- 모션을 내부 포맷으로 저장할 때는 VRMA로 통일하는 편이 유리하다. 표준이고, 어떤 VRM에도 리타깃되며, three-vrm·UniVRM·Blender 모두에서 읽힌다.
- VRoid Hub API로 사용자의 VRM을 가져오는 연동은 가능하다. 다만 OAuth 앱 등록이 필요하고, 다운로드 라이선스 조건을 지켜야 한다.

### Gaps
- VRM 0.x 메타(`allowedUserName`, `commercialUssageName` 등) 필드 정의는 이번에 원문으로 확인하지 못했다. 다만 VRM 0.x 모델이 아직 많이 쓰이므로 두 버전 모두 파싱해야 할 것이다.
- VRMA 스펙이 "정식 릴리스"된 정확한 날짜를 vrm.dev 페이지에서 찾지 못했다.
- VRM Consortium의 2026년 조직·표준화 동향(ISO 등)은 확인하지 못했다.
- VRoid Hub API 이용약관에서 다운로드한 모델로 영상을 렌더링하는 것이 허용되는지는 확인하지 못했다.

## 2. 3D 아바타 제작: VRoid Studio, Ready Player Me, Character Creator, AI 이미지→3D 아바타

### Takeaway
VTuber용 3D 아바타 제작의 사실상 표준은 여전히 VRoid Studio(무료, VRM 1.0 기본 출력)다. Ready Player Me는 2025년 12월 Netflix에 인수된 뒤 2026-01-31에 공개 서비스와 API가 모두 종료되어 사용할 수 없다. 이미지에서 3D 애니메 캐릭터를 만드는 연구 코드(CharacterGen, StdGEN)와 자동 리깅(UniRig)은 오픈소스(Apache/MIT)로 공개돼 있다. 반면 Tencent Hunyuan3D 2.0 라이선스는 **한국·EU·영국에서 적용되지 않는다(사용 불가)**는 점에 주의해야 한다.

### Inferences
- stream2clip이 아바타를 "만들" 필요는 거의 없다. VTuber 본인이 가진 VRM(대개 VRoid Studio나 BOOTH 제작물)을 받아 쓰는 구조가 현실적이다.
- AI 아바타 생성은 "3D 모델이 없는 2D/Live2D VTuber용 간이 3D 프리뷰" 같은 실험적 기능에서만 고려할 만하다.
- CharacterGen과 StdGEN의 출력물은 리깅된 VRM이 아니다. 실제로 쓰려면 리깅(UniRig 등), VRM 변환(Blender + VRM Add-on), 표정·스프링본 설정 같은 후처리 파이프라인이 필요할 것이다.
- 한국 사용자·사업자라면 Hunyuan 계열 모델(3D 생성. 아래 HY-Motion도 해당 여부 확인 필요)은 라이선스상 사용할 수 없을 가능성이 높으므로 제외하는 것이 안전하다.
- Ready Player Me 기반 튜토리얼과 코드는 모두 폐기 대상으로 표시해야 한다.

### Gaps
- Reallusion Character Creator(CC4/CC5)의 2026년 버전, 가격, VRM 내보내기 지원 여부는 조사하지 못했다.
- Tripo·Meshy 등 상용 text/image-to-3D 서비스의 2026년 가격, API, 애니메 아바타 품질, 자동 리깅 및 VRM 출력 지원 여부는 확인하지 못했다.
- VRoid Studio로 만든 모델의 이용 조건(제작자 측 라이선스)과 VRoid Plus 구독의 기능 범위는 원문으로 확인하지 못했다.

## 3. 모션 캡처: 웹캠, 폰 ARKit, 풀바디 트래커, 영상→모션 AI (오프라인 렌더용 BVH/FBX/VRMA 출력)

### Takeaway
웹캠 실시간 트래킹은 MediaPipe(Apache-2.0, 활발)를 기반으로 하는 것이 표준이다. 그 위의 Kalidokit은 사실상 유지보수가 멈췄다. 영상 파일에서 바로 VRM 호환 모션 파일(VMD/BVH/glTF)을 뽑을 수 있는 무료 도구로는 XR Animator가 가장 실용적이다. 연구용 영상→3D 인체 모션 모델 중 GVHMR은 상업 이용이 금지돼 있고, 4D-Humans와 WHAM은 MIT, FreeMoCap은 AGPL이다. stream2clip처럼 "녹화된 방송 영상에서 모션을 추출"하는 시나리오에서는 라이선스가 핵심 변수다.

### Inferences

## 4. 모션 생성 AI (text-to-motion, music-to-dance)와 MMD 생태계

### Takeaway
주요 연구 모델(MDM, MotionGPT, MoMask, EDGE)은 코드가 MIT이지만 대부분 2024~2025년 이후 정체 상태다. 출력은 SMPL·HumanML3D 골격이라 VRM에 쓰려면 리타깃이 필요하다. 2026년 기준 가장 활발한 오픈 모델은 Tencent HY-Motion 1.0(2025-12 공개, FBX 리타깃 경로 제공)이지만 라이선스가 커스텀이다. MMD 쪽에서는 three.js 공식 MMDLoader가 r172에서 제거됐고 커뮤니티 패키지(@yohawing/three-mmd-loader, babylon-mmd)로 넘어갔다. VMD를 VRMA로 바로 변환하는 공개 도구는 찾지 못했다.

- VRM이나 VRMA를 직접 출력하는 text-to-motion 또는 music-to-dance 모델은 찾지 못했다.
- 그 밖의 음악→댄스 모델(예: 2025~2026 신작)과 상용 서비스(DeepMotion SayMotion 등)는 조사하지 못했다.

## 5. 3D VTuber 방송·제작 소프트웨어 (오픈소스 또는 스크립팅 가능 여부 중심)

### Takeaway
3D VTuber 실방송 앱 중 오픈소스는 VMagicMirror(MIT)와 VirtualMotionCapture(MIT)뿐이다. Warudo는 클로즈드 소스이지만 C# 플러그인 SDK와 Blueprints(비주얼 스크립팅)로 가장 깊게 확장할 수 있고, 개인 사용은 무료다. VSeeFace는 무료·클로즈드이고 VRM 0.x만 지원한다는 보고가 있다. 웹 기반 오픈소스 "AI 캐릭터" 앱(ChatVRM, Amica, AITuber Kit)은 three-vrm 렌더링, 립싱크, 표정 제어의 참고 코드로 유용하다.

### Cited Findings
- **Warudo**:
  - Blueprints(플로우차트형 비주얼 스크립팅)와 C# 스크립팅(`Warudo.Core`, 내장 기능과 같은 API)을 제공한다.
  - 플러그인은 Plugin 클래스를 상속한 C# 스크립트를 담은 mod로 배포하며, Steam Workshop으로 공유할 수 있다.
  - 코드로 Blueprint 그래프를 생성할 수 있다. Playground로 테스트하려면 .NET 8 SDK가 필요하다.
  - — [Scripting overview](https://docs.warudo.app/docs/scripting/overview), [Plugin Mod](https://docs.warudo.app/docs/scripting/plugin-mod), [Generating Blueprints](https://docs.warudo.app/docs/scripting/api/generating-blueprints)
- Warudo는 Steam 등록 정보 기준으로 개인 사용 무료라고 보도됐다. 상업 라이선스 조건은 공개 페이지에 명시되지 않았다고 한다(listicle 출처라 검증 필요). — [tech-insider 2026 비교](https://tech-insider.org/vtube-studio-vs-vseeface-vs-warudo-2026/)

- **AITuber Kit**: ★1,148 / 2026-11-12. **커스텀 듀얼 라이선스**로, 비상업 이용은 무료이고 상업 이용은 상용 라이선스가 필요하다. — [GitHub](https://github.com/tegnike/aituber-kit), [LICENSE](https://cdn.jsdelivr.net/gh/tegnike/aituber-kit@main/LICENSE)

### Inferences
- stream2clip이 직접 연동할 실익이 큰 것은 Warudo다. 3D VTuber 점유율이 높고 C# 플러그인으로 이벤트·모션 로그를 외부에 내보낼 수 있을 것으로 보인다. 다만 클로즈드 소스이므로 "플러그인 형태의 옵션 연동"으로 한정하는 것이 바람직하다.

- Warudo의 최신 버전(일부 출처는 0.15.0, 2026-06이라 함)과 상업 라이선스 조건은 공식 출처로 확인하지 못했다.

## 6. VRM의 헤드리스·오프라인 영상 렌더링 (three.js + Puppeteer, Blender CLI, Unity batch)

### Takeaway
"VRM + 모션 → MP4"를 한 번에 해 주는 기성 오픈소스 프로젝트는 찾지 못했다. 다만 구성 요소는 모두 있다. three-vrm(+VRMA), 프레임 단위 seek 렌더러(Remotion, Puppeteer 프레임 캡처, @headless-three/renderer), ffmpeg 인코딩을 조합하면 된다. Blender(VRM Add-on은 5.3까지 지원)를 `-b` 배치 모드로 돌리는 방식도 대안이다.

### Cited Findings
- **@headless-three/renderer**: Node.js에서 wgpu로 Three.js 씬을 렌더링하는 헤드리스 렌더러다. 브라우저 없이 PNG나 raw RGBA를 출력하고, README에 three-vrm 로드·업데이트·렌더 예제가 있다. 영상 인코딩은 직접 해야 한다. MIT이고 0.4.5(2026-10-06)이다. — [npm](https://registry.npmjs.org/@headless-three/renderer), [pkgstats](https://www.pkgstats.com/pkg:@headless-three/renderer)
- **Remotion** (React로 영상을 프로그래밍): ★73,943 / 2026-11-17.

- **vrm-toolkit-mcp `vrma_preview`**: 로컬 헤드리스 Chrome/Edge에서 VRM에 VRMA를 적용해 PNG 스냅샷이나 10초 이하 WebM을 만든다. — [Glama](https://glama.ai/mcp/servers/dwarehouse1/vrm-toolkit-mcp/tools/vrma_preview)
- **VRM Add-on for Blender**는 Blender 2.93~5.3을 지원한다. — [GitHub](https://github.com/saturday06/VRM-Addon-for-Blender)
- **Unity 배치 처리**: Python과 Unity 빌드로 VRM 애니메이션 처리를 자동화하는 방법을 묻는 Unity 포럼 스레드가 있다. 해법이 확립돼 있지는 않은 것으로 보인다. — [Unity Discussions](https://discussions.unity.com/t/is-it-possible-to-automate-vrm-animation-processing-with-python-and-unity-game-build/1606721)

### Inferences
- stream2clip에 맞는 권장 구성(웹 스택 기준): **three-vrm + three-vrm-animation으로 씬 구성 → 프레임 시각을 결정론적으로 seek → 프레임 캡처(Remotion `@remotion/three`, Puppeteer, @headless-three/renderer 중 택1) → ffmpeg 합성(방송 원본 영상, 자막과 합성)**.
  - Remotion은 숏폼 편집 타임라인, 자막, 오버레이까지 한 번에 처리할 수 있어 생산성이 가장 높다. 단, 회사 규모에 따라 라이선스 비용이 생긴다.
  - GPU가 없는 서버 환경에서는 @headless-three/renderer(wgpu)가 브라우저 없이 동작할 수 있어 유망하다. 아직 0.x 버전이라 MToon 셰이더 호환성 검증이 필요하다.
- Blender CLI 경로는 품질(Eevee/Cycles, 툰 셰이딩)이 가장 좋을 수 있지만 렌더 시간과 서버 부담이 크다. "고품질 렌더" 옵션으로 두는 편이 맞다.
- Unity batch mode는 라이선스(Unity 런타임 정책)와 헤드리스 렌더링 복잡도 때문에 1순위로 권장하기 어렵다.

### Gaps
- 실제 프로덕션에서 three-vrm(MToon)을 Puppeteer나 wgpu 헤드리스로 렌더링했을 때의 속도와 셰이더 호환성 벤치마크는 찾지 못했다.
- Blender CLI + VRM Add-on으로 VRMA를 적용해 배치 렌더링하는 공개 스크립트나 프로젝트는 찾지 못했다.
- Remotion 5.0 라이선스 변경의 구체적 내용은 확인하지 못했다(PR #3750 참조).

## 7. 종합: stream2clip에 가장 재사용 가치가 높은 항목

### Takeaway
1순위 재사용 스택은 다음과 같다.
- **@pixiv/three-vrm + @pixiv/three-vrm-animation (MIT)**: 렌더링.
- **VRM 1.0 meta (스펙)**: 권한 자동 검사.
- **VRMA (스펙)**: 모션 표준 포맷.
- **MediaPipe (Apache-2.0)**: 영상에서 모션·표정 추출.
- **Remotion 또는 Puppeteer/@headless-three + ffmpeg**: 오프라인 렌더.
- 보조 후보: VRM Add-on for Blender(MIT, 고품질 배치 렌더), VMC 프로토콜(방송 중 원본 모션 녹화), XR Animator(영상→VMD/BVH 수동 변환).

라이선스 회피 대상은 다음과 같다.
- GVHMR, Bailando: 비상업 전용.
- FreeMoCap: AGPL.
- AITuber Kit: 상업 이용 시 유료.
- Hunyuan3D 2.0: 한국·EU·영국 적용 제외.
- HY-Motion: 라이선스 원문 확인 필요.
- Ready Player Me: 서비스 종료.

### Inferences
- stream2clip의 핵심(방송 → 클립·쇼츠)은 2D 영상 편집이다. 3D는 다음 세 가지 부가 기능으로 단계적으로 도입하는 편이 현실적이다.
  - 3D VTuber의 VRM으로 숏폼용 리액션, 인트로, 아웃트로 컷을 자동 생성하는 기능.
  - 방송에서 추출하거나 VMC로 녹화한 모션을 VRMA로 저장해 하이라이트 장면을 다른 카메라 앵글로 재렌더링하는 기능.
  - 댄스·제스처 VRMA 프리셋을 적용하는 기능.
- 모든 3D 자산(VRM, VMD, VRMA)에 대해 라이선스와 크레딧 메타데이터를 처리 파이프라인의 1급 데이터로 다뤄야 한다. VRM은 이를 스펙으로 제공하므로 자동화할 수 있다.
