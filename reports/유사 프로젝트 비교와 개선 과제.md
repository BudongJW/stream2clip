# 검출 다음의 빈칸을 채울 stream2clip 개선 과제

채팅 급증 기반 하이라이트 검출은 2025~2026년 사이 방송 플랫폼과 저가 서비스의 기본 기능이 되어 더 이상 stream2clip만의 차별점이 아님. YouTube는 라이브 방송의 주요 순간을 Shorts로 만드는 AI 기능을 발표했고([YouTube Blog](https://blog.youtube/news-and-events/live-updates/)), Twitch는 채팅, 목소리 억양, 화면 이벤트로 자막 달린 클립을 만드는 Auto Clips 베타를 예고했으며([Twitch Blog](https://blog.twitch.com/en/2026/05/30/everything-we-announced-at-twitchcon-rotterdam-2026/)), 한국 Captus와 일본 KIRARI는 CHZZK, SOOP, VTuber 다시보기의 채팅 분석과 방송 후 자동 분석을 제공([Captus](https://captus.kr/), [KIRARI](https://www.kirari.io/blog/ai-clip-tools)). 2026년 오픈소스 클리퍼는 선택형 LLM 판정, MCP, 다중 플랫폼 게시를 기본 구성으로 갖추고, 상위 신작 다수는 사용자 평가와 게시 성과를 랭킹에 되먹이는 학습 루프까지 보유. 반면 **VTuber 아바타 인식, 기획사 가이드라인과 재사용 콘텐츠 점검, 화자 색 자막, 가로 클립과 모음 영상, 시청자 댓글 타임스탬프 기반 평가**를 함께 갖춘 도구는 조사 범위에 없어 stream2clip의 우위 유지. 따라서 개선의 중심은 새 검출 신호보다 검출 앞뒤 공정. 받아쓰기 품질(전사 단계 이름 용어집, 큰 Whisper 모델 선택지), 평가 데이터로 검출 가중치를 맞추는 루프, 방송 후 자동 처리, 자막 스타일 체계, 플랫폼 API 변화 대응(Shorts 사용자 썸네일 업로드)이 핵심. **1순위 9개는 기존 데이터와 의존성만으로 구현 가능하고 라이선스 위험 없음.** 선택형 LLM, 학습형 오디오 태거, 화자 분리는 사용자가 설치하는 선택 기능으로 두되 가중치 라이선스(HF 게이트, 비상업, 지역 제외) 확인 필수. 화면 미세 변형, 탤런트 음성 복제, AI B롤, 무인 공개 업로드는 의도적 제외 대상.

함의는 두 갈래. 첫째, 플랫폼 기능은 본인 채널 영상이나 공식 중계만 다루므로 키리누키 편집자의 핵심 작업(남의 방송 탐색, 번역, 조판, 권리 점검)은 여전히 빈칸. 둘째, 자기 방송을 자르는 VTuber에게는 Twitch Auto Clips와 YouTube 라이브 하이라이트가 무료 대체재이므로, stream2clip의 라이브 모드와 방송 기록기는 플랫폼이 하지 않는 부분(아바타 별도 녹화 합성, 가로 모음, 화자 색 자막, 여러 플랫폼 원본 처리)으로 차별화 필요. 상용 서비스는 스트림 전용 기능을 월 $25~40 요금제에 묶어 두고 있어 무료 무제한 로컬 도구의 비용 우위는 분명([StreamLadder](https://www.streamladder.com/pricing), [Eklipse](https://eklipse.gg/compare/eklipse-vs-crossclip))

사용자 불만은 클라우드 특유 문제와 품질 문제로 나뉨. 앞쪽은 시간과 크레딧 이중 차감, 실패 작업의 크레딧 소모, 구독 종료 후 프로젝트 소실, 잦은 장애([Trustpilot OpusClip](https://www.trustpilot.com/review/opus.pro?page=2)), 무료 3일과 Starter 29일의 미디어 만료([OpusClip 요금](https://www.opus.pro/pricing)). 뒤쪽은 생성 클립 10개 중 3개 정도만 쓸 만하다는 적중률 불만, 어색한 시작과 끝, 자막 오류([G2 OpusClip](https://www.g2.com/products/opusclip)), 단일 토킹헤드 전제의 facecam 오인(경쟁사 주장, [ClipMe](https://clipme.com/best-ai-clipper-for-gaming)). 앞쪽은 로컬 도구가 구조적으로 피하는 문제이고, 뒤쪽이 stream2clip이 대비할 몫

오픈소스 쪽 불만은 품질보다 설치와 외부 의존성 변화에 몰림. AssemblyAI 파라미터 폐기로 전사 실패([SupoClip #56](https://github.com/FujiwaraChoki/supoclip/issues/56)), yt-dlp HTTP 403([AI-Youtube-Shorts-Generator issues](https://github.com/Anil-matcha/AI-Youtube-Shorts-Generator/issues)), 게임 방송 3시간 분석에 DeepSeek 요금 2.3위안이 들고 과금이 계속된 사고([autoclip #175](https://github.com/zhouxiaoka/autoclip/issues/175))가 대표 사례. 버전 고정과 구성요소 점검이 신뢰성을 좌우하며, stream2clip의 `setup` 명령과 구성요소 점검 창은 이미 이 방향

## 3. 아바타 인식, 권리 점검, 가로 형식은 여전히 stream2clip 고유 영역

| 항목 | stream2clip 현재 | 경쟁 상황 |
|:---:|---|---|
| 아바타 인식 레이아웃 | 애니메 얼굴 검출로 아바타 박스 제안, 별도 아바타 영상(그린스크린, 알파) 합성, 방송 기록기의 VTube Studio 외곽선 | 조사한 클리퍼는 모두 실사 얼굴 추적(MediaPipe, YOLO, UltraFace, TalkNet) 전제([OpenShorts](https://github.com/mutonby/openshorts), [Clips Kitty](https://github.com/ColinGPT9/clips-studio), [reelsaw](https://github.com/osbytes/reelsaw)) |
| 기획사 가이드라인, 재사용 콘텐츠 점검 | 4개 기획사 프로필, 원본 표기 설명란, 아카이브 공개, 채널 등록, AI 표기, 재사용 콘텐츠 점검, VRM 사용 조건 검사 | 플랫폼과 상용 서비스에 기획사 규칙 점검 없음. 2026년 일본 AI 서비스는 세로 Shorts 초안 수준([KIRARI 가이드](https://www.kirari.io/blog/vtuber-clip-guide)) |
| 화자 색 자막 | whisperX, RTTM, 마이크별 트랙으로 화자별 색 | OpusClip은 출시 예정 표기([OpusClip 요금](https://www.opus.pro/pricing)) |
| 가로 클립과 모음 영상 | Shorts, 가로 1~3분, 챕터 있는 모음 프리셋, 상황 설명, 최고 순간 미리 보기 | Captus, KIRARI는 세로 숏폼 초안 중심([Captus](https://captus.kr/), [KIRARI](https://www.kirari.io/blog/ai-clip-tools)) |
| 슈퍼챗, heatmap 신호 | 방송별 기준선 robust z 융합 | 중국 도구 일부만 유사. hotclip은 SC, 舰长, 선물을 상호작용 등급별로 가중([hotclip](https://github.com/xixihhhh/hotclip)), douyin-living은 선물, 좋아요 이벤트 수집([douyin-living](https://github.com/CipherNoct/douyin-living)) |
| 약한 라벨 평가 | `evaluate`: 시청자 댓글 타임스탬프 대비 precision, recall, 무작위 대비 배수 | 정량 평가 도구를 공개한 곳은 douyin-living, hotclip, reelsaw 정도 |
| 비용과 보존 | 무료, 로컬, 만료 없음 | 클라우드 서비스는 요금제별 원본 길이 상한과 미디어 만료([Reap 보고서](https://reap.video/reports/state-of-top-ai-video-clipping-tools-2026)) |
| 음원 라이선스 추적 | BGM, 효과음의 출처와 라이선스 기록, 설명란 크레디트와 업로드 전 점검 | 비교한 클리퍼 README에서 확인된 사례 없음 |

앞선 조사의 "슈퍼챗과 멤버십을 신호로 쓰는 오픈소스는 없음"이라는 판단은 hotclip과 douyin-living 확인으로 수정 필요. 다만 두 도구 모두 중국 플랫폼 대상이고 hotclip은 AGPL

## 4. 개선 과제 우선순위: 1순위는 기존 데이터를 다시 쓰는 작은 작업 9개

1순위는 이미 가진 데이터(채팅, 신호 곡선, 자막, 썸네일, 이름 용어집)를 다시 쓰는 작업, 2순위는 새 처리 단계나 선택 설치 모델이 필요한 작업, 3순위는 수요가 좁거나 유지 부담이 큰 작업

### 1순위: 기존 자산 재사용, 라이선스 위험 없음

## 5. 라이선스 위험은 코드보다 가중치와 숨은 의존성에서 발생

## 결론

조사 전에는 기능 목록의 빈칸(LLM, 다중 게시, B롤)을 채워야 경쟁력이 생긴다는 가정이 자연스러웠으나, 실제 경쟁 축은 순간을 찾는 일에서 그 뒤의 순환을 닫는 일로 이동. 플랫폼이 자기 방송 클립을 무료로 뽑기 시작하면서 검출 정확도의 절대값보다 채널마다 맞춰지는 속도와 사람이 고치는 비용이 승부처가 되었고, 이 영역에서 stream2clip은 시청자 댓글 타임스탬프 평가라는 드문 출발점을 이미 보유. 가중치 조정, 채택 기록, 게시 성과 회수를 하나의 로컬 루프로 묶으면 클라우드 서비스가 사용자 데이터를 모으지 않고는 하기 어려운 채널별 최적화가 무료로 가능하고, 이 루프가 이후 LLM 보조나 오디오 태거 같은 선택 기능의 효과를 판정하는 기준선 역할까지 겸함

두 번째 함의는 업로드와 라이선스가 기능이 아니라 유지 대상이라는 점. 2026년 11월 한 달 사이 YouTube Data API는 공개 범위 기본값, 유료 PPL 기본값, Shorts 썸네일을 연달아 바꿨고, 가장 유망한 모델들은 코드보다 가중치에서 비상업, 게이트, 지역 제외 조건을 붙임. 권리를 점검하는 클립 도구라는 stream2clip의 정체성은 이런 변화를 빠르게 따라가는 회귀 테스트와 플러그인 경계로 유지되며, 화면 미세 변형, 음성 복제, 무인 공개 업로드를 하지 않는다는 제외 목록도 그 정체성의 일부
