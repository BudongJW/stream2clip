## 하이라이트 점수 계산

방송을 `--window`(기본 5초) 단위로 분할하고, 신호별로 해당 방송의 평소 수준(중앙값, MAD)과 비교한 robust z-점수를 가중합. 채팅이 적은 채널과 많은 채널에 동일 기준 적용 가능

| 신호 | 의미 | 가중치 |
|:---:|---|:---:|
| 채팅 속도 | 구간당 메시지 수 | 0.30 |
| 고유 채터 | 1명의 도배보다 여러 명의 반응을 반영 | 0.20 |
| 반응 어휘 | 草, ｗｗ, 문장 끝의 ｗ 1개, 笑, lol, KEKW, ㅋㅋ, ㄷㄷ, 888, かわいい, ???, ！？, "え？" 등 감탄사 단독 메시지. 메시지당 1회 집계 | 0.30 |
| 후원 | 슈퍼챗, 비트, 멤버십, 선물 | 0.10 |
| 음량 | `--audio` 지정 시 영상 소리의 RMS(dB) | 0.15 |
| 많이 다시 본 구간 | `--info` 지정 시 YouTube heatmap | 0.15 |

점수 계산 이후의 처리 순서:

1. 이동 평균 적용
2. 임계값(`--threshold`, 기본 2.0)을 넘는 봉우리 선택
3. 채팅 지연 보정(`--delay`, 기본 8초 앞당김)
4. 앞뒤 여유 추가(`--lead` 20초, `--tail` 10초)
5. 15초 이내 구간 병합
6. 길이를 15~90초로 조정
7. 점수순 상위 `--top`개 선택

각 구간에는 "채팅 급증 268/분 (평소의 11.2배), 반응 60개 (웃음 60), 음량 +26 dB" 형식의 근거 첨부

채팅 신호에서 제외하는 항목:

| 항목 | 사유 | 비고 |
|:---:|---|---|
| 인사, 작별 | "こんぺこ～", "おつかれ", "hello", "안녕하세요" 등은 방송 시작과 종료 시점에 집중되어 하이라이트로 오인 | `--keep-greetings`로 해제. 슈퍼챗은 계속 집계 |
| 대기실 채팅 | YouTube 다시보기에서 전부 0초로 기록 | 보낸 시각이 방송 시작 시각과 맞지 않으면 제외 |

## 실제 방송으로 확인한 기본값

- 대상: 공개 아카이브 1개(게임 방송 85분, 채팅 약 44,000개, 분당 약 520개, YouTube 다시보기, 자동 자막, 480p 영상)
- 방법: `fetch`, `auto`를 기본 설정으로 실행
- 유의: 방송 1개의 결과이므로 참고 수치. 채팅이 적은 채널이나 다른 장르에서는 결과가 다를 수 있음

| 항목 | 확인 내용 | 조치 |
|:---:|---|---|
| 반응 어휘 | 최초에는 메시지의 11%만 반응으로 분류. 실제 채팅은 문장 끝의 `ｗ` 1개, "え？", "！？", 채널 이모티콘으로 반응 | 어휘 추가 후 40% |
| 인사, 작별 | 종료 인사("おつぺこ～" 등 마지막 2분에 약 300개)가 10개 중 8위로 선정 | 인사, 작별 제외 후 해당 순위에 실제 장면 선정 |
| 대기실 채팅 | 방송 시작 전 메시지 49개가 0초에 집중 | 보낸 시각 기준으로 제외 |
| `--delay` 8초 | 가장 큰 소리가 난 40개 순간 기준으로 채팅 반응은 약 6초 후 최고조(평소의 3.5배), 3초와 9초에도 2.8배 이상 | 분석 단위(5초) 이내의 차이이므로 8초 유지. 초저지연 방송은 `--delay 5` 수준 권장 |
| `--threshold` 2.0 | 채팅이 많은 방송은 봉우리도 평소의 2~2.7배 수준이며 최고 점수 2.9. 임계값별 결과 수는 1.5에서 18개, 2.0에서 10개, 2.5에서 2개, 3.0에서 0개 | 유지. 상향 시 이러한 방송에서는 결과가 거의 없음 |
| `--lead` 20초, `--tail` 10초 | 선정 구간의 자동 자막상 상황 설명부터 반응까지 한 구간에 포함. 직접 시청 확인은 미실시 | 유지 |
| 음량 가중치 0.15 | 방송 전체 기준 음량과 채팅량의 상관은 약함(0.06). 큰 소리 직후에는 반응 증가 | 보조 신호로 유지 |
| 많이 다시 본 구간 | 게시 직후 영상이라 heatmap이 비어 있음 | 미검증 |
| `--transcribe small --language ja` | 최초 실행 실패(faster-whisper 1.2.1이 PyAV 19로 파일을 열지 못함). 수정 후 90초 클립을 CPU에서 71초에 받아써 자막 24개 생성, 단어 단위 강조를 프레임으로 확인 | 오디오를 ffmpeg로 디코딩하여 전달하도록 수정. 최초 실행 시 모델(약 460MB) 다운로드 시간 추가 |
| YouTube 자동 자막 VTT | 단어 시각이 포함되어 그대로 카라오케 적용 가능. 자막 한 줄이 다음 줄이 나올 때까지 화면에 유지(Whisper는 발화 종료 시 사라짐) | 유지 |

## 여러 방송 평가

기본값을 방송 1개로만 정하면 해당 방송에 맞춰지는 문제가 있어 `evaluate` 명령으로 여러 방송을 평가

- 방법: 채팅만으로 하이라이트를 검출하고 시청자가 댓글에 남긴 타임스탬프("1:23:45 여기 웃김")와 비교
- 기준의 성격: 정답은 아니나 사람이 선정한 순간이며, 인기 아카이브 대부분에 존재하고 별도 표시 작업이 불필요

```bash
stream2clip fetch "https://www.youtube.com/watch?v=VIDEO_ID" -o data/VIDEO_ID --comments 150
```

```bash
stream2clip evaluate data/* --sweep threshold=1.5,2,2.5 --sweep delay=4,8,12
```

| 값 | 의미 |
|:---:|---|
| precision | 검출한 하이라이트 중 시청자가 표시한 순간이 포함된 비율 |
| recall | 시청자가 표시한 순간 중 하이라이트에 포함된 비율 |
| chance | 동일 길이의 구간을 임의 위치에 두었을 때 기대되는 precision |
| lift | precision ÷ chance. 1보다 크면 무작위보다 우수 |

### 평가 결과

- 대상: 공개 아카이브 7개(2026-11-19 측정, 62~106분 방송, 일본어 5개, 영어 2개)
- 조건: 채팅만 사용, 방송당 최대 10개, 허용 오차 10초, 인기 댓글 53~150개에서 얻은 표시 196곳

| 설정 | 클립 | precision | chance | lift | recall |
|---|:---:|:---:|:---:|:---:|:---:|
| **기본값** (`--threshold 2.0`, `--delay 8`, `--lead 20`) | 60 | 52% | 40% | **1.28** | 23% |
| `threshold=1.5` | 70 | 51% | 45% | 1.13 | 26% |
| `threshold=2.5` | 52 | 52% | 37% | 1.40 | 19% |
| `threshold=3.0` | 41 | 51% | 34% | 1.49 | 14% |
| `delay=4`, `delay=12` | 60 | 53%, 52% | 40% | 1.33, 1.28 | 23%, 22% |
| `lead=10`, `lead=30` | 61, 59 | 49%, 51% | 37%, 42% | 1.32, 1.21 | 21%, 23% |
| `window=10` | 46 | 57% | 39% | 1.43 | 18% |

2명 이상이 동일 순간을 표시한 곳만 사용한 경우(`--min-votes 2`, 방송 5개, 57곳): 기본값은 precision 23%, chance 16%, lift 1.42. `threshold=2.5`는 lift 1.94

### 해석 및 한계

- 기본값은 무작위보다 우수하나 차이는 크지 않음(1.3~1.4배). 방송별 편차가 커서(lift 0.47~4.68) 방송 7개로는 설정값 간 0.1~0.2 차이를 판별할 수 없으므로 기본값은 변경하지 않음
- 임계값 상향 시 무작위 대비 배수는 개선되나 클립 수가 감소하며, 3.0에서는 방송 1개의 결과가 0개. 확실한 장면만 필요한 경우 `--threshold 2.5`가 근거 있는 선택
- `--delay`와 `--lead`는 이 자료에서 차이 없음
- 타임스탬프 댓글은 정밀하지 않은 기준. 방송의 목차처럼 화제 전환마다 기재한 댓글이 포함되어, 표시가 54~56곳인 방송 2개는 임의 위치를 선택해도 70~81%가 일치
- 채팅 반응이 없는 조용한 명장면은 이 평가 방법과 채팅 검출 모두에서 검출 불가
- CHZZK, SOOP 다시보기는 댓글 타임스탬프 관행이 달라 평가 대상에서 제외

## 라이브 모드 기본값

### 검출 방식

| 항목 | 내용 |
|:---:|---|
| 점수 | 5초 구간마다 채팅 수, 참여자 수, 반응 어휘, 후원을 직전 15분의 구간과 비교. 다시보기 검출과 동일한 robust z-점수 사용 |
| 판정 시점 | 구간이 확정된 이후에만 판정. 다음 구간의 메시지가 도착했거나 지연 허용 시간(`--lag`)이 경과한 경우 |
| 시각 기준 | 도착 시각이 아닌 메시지에 기록된 시각 사용. yt-dlp가 라이브 채팅을 약 10초 단위 묶음으로 전달하기 때문 |
| 평활 | 점수를 2개 구간(10초) 평균으로 계산(`--smooth 2`)하여 1개 구간만 높은 잡음 억제. 매우 큰 급증은 1개 구간만으로도 발동 |
| 준비 시간, 간격 | 시작 후 2분은 관찰만 수행(`--warmup`), 클립 간 최소 간격 90초(`--cooldown`) |
| 최소 메시지 수 | 구간당 8개(`--min-messages`) |

### 종료된 방송 7개 측정 결과

- 대상: 여러 방송 평가에 사용한 공개 아카이브 7개(9시간, 시청자 댓글 타임스탬프 196곳)
- 방법: 채팅을 처음부터 순서대로 입력하여 해당 시점까지의 채팅만으로 발동한 위치를 댓글과 비교

| 설정 | 시간당 발동 | precision | 무작위 기대값 | 배수 |
|---|:---:|:---:|:---:|:---:|
| `--threshold 3.0` | 8.3 | 34.7% | 25.8% | 1.34 |
| **`--threshold 3.5` (기본)** | 6.4 | 34.5% | 26.0% | 1.33 |
| `--threshold 4.0` | 4.4 | 40.0% | 26.2% | 1.53 |
| `--threshold 5.0` | 3.1 | 42.9% | 26.7% | 1.60 |
| 참고: 다시보기 검출, 방송당 상위 10개 | 6.7 | 51.7% | 40.2% | 1.28 |

- 라이브 모드의 클립은 35초로 짧아 precision과 무작위 기대값이 함께 낮음. 비교 대상은 배수
- 이후의 채팅을 볼 수 없는 조건에서도 배수는 다시보기 검출과 유사(1.3 내외)
- 방송 7개로는 0.1~0.2 차이를 판별할 수 없으므로, 기본 임계값은 정확도가 아닌 발동 횟수가 다시보기 검출(시간당 6~7개)과 유사해지는 값으로 선정

### 실제 방송 관찰에 따른 조정

- 대상: 기본 설정으로 실제 방송 1개(분당 약 10개의 느린 채팅)를 30분 관찰
- 결과: 메시지 5~7개 구간에서 6회 발동(시간당 12회)
- 조치: 구간당 최소 메시지 수를 5에서 8로 상향. 동일 조건에서 2회 발동. 채팅이 많은 방송 7개의 결과는 변동 없음
- 한계: 방송 1개의 관찰 결과에 근거

## 아바타 박스 결정 방식

아바타는 방송 중 동일 위치에 있으므로 프레임 단위로 추적하지 않고 방송 1개에 박스 1개를 결정

1. 방송 길이의 8%~92% 구간에서 프레임 12장(`--avatar-samples`)을 균등 추출
2. 각 프레임에서 애니메 얼굴 검출([deepghs/anime_face_detection](https://huggingface.co/deepghs/anime_face_detection) `face_detect_v1.4_n`, ONNX 12MB, onnxruntime CPU)
3. 여러 프레임의 동일 위치에 계속 나타나는 얼굴을 아바타로 판정. 게임 캐릭터나 섬네일 속 얼굴은 나타났다 사라지나 아바타는 유지됨. 추출 프레임의 40% 이상에서 검출되어야 함
4. 머리가 움직인 범위를 포함하도록 얼굴 높이의 약 3배 크기로 확장하고, 머리카락, 귀, 모자를 고려하여 위쪽 여유를 추가. 가로세로 비율은 stack 레이아웃의 아바타 칸에 맞춤

| 항목 | 내용 |
|:---:|---|
| 모델 보관 | 최초 사용 시 1회 다운로드하여 `~/.cache/stream2clip` 또는 `STREAM2CLIP_MODEL_DIR`에 보관. 고정된 SHA-256과 불일치 시 사용 안 함 |
| 오프라인 사용 | `--face-model model.onnx`로 파일 지정 |
| 측정 결과 | 실제 방송 1개(480p, 85분)에서 12장 전부에서 아바타 얼굴 검출, 소요 시간 2.9초 |
| 검출 불가 | 아바타가 화면에 없거나 계속 이동하는 방송. 이 경우 `--avatar x,y,w,h`로 직접 지정하도록 안내 |
