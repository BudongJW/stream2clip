# 실환경 검증 현황

자동 테스트와 별도로 실제 기기, 실제 서비스에서 확인한 범위와 미검증 범위. 요약은 README의 [알려진 제약](../README.md#알려진-제약) 참조

## 운영체제 및 화면

| 환경 | 검증 내용 | 미검증 |
|:---:|---|---|
| Windows 11 | 실기기(1920×1080, 배율 125%, 모니터 1대)에서 전역 단축키 F8, F9(앱이 숨겨진 상태 포함), 커서 합성, 선택 영역과 캡쳐 및 녹화 결과의 일치, GIF, MP4, WebP, WebM, 투명 배경, 클립보드 복사 | 배율 100%, 150%, 175%는 동일 기기에서 Qt 배율 계수(`QT_SCALE_FACTOR`)로만 확인. 배율이 다른 모니터 2대 |
| Windows 10 | 없음 | 동일한 Win32 API를 사용하나 실기기 미검증 |
| macOS | 없음 | 실기기 미검증. 시스템 설정의 화면 기록 권한 필요 |
| Linux (X11) | Xvfb에서 전체 절차 테스트 | 실기기 |
| Wayland | 없음 | 화면 캡쳐(mss)는 X11, XWayland에서만 동작 |

## 화면 언어

- 앱 화면 문구는 한국어, 일본어, 영어 제공. Windows 11에서 3개 언어 모두 화면을 표시하여 배치 확인
- 하이라이트 근거("채팅 급증"), 가이드라인 점검 문구, 설명란 양식, 명령줄 출력은 한국어만 제공
- 일본어, 영어 번역은 원어민 검수 미실시

## 설치 프로그램

- GitHub Actions의 Windows 러너에서 빌드 후 3개 언어로 자동 설치, 설치된 프로그램의 시작 언어와 제거 확인
- 언어 선택 창 표시 확인(러너 화면 캡쳐)
- 미검증: 화면을 직접 조작하는 수동 설치
- 코드 서명 미적용. Smart App Control 사용 PC에서 3회 빌드한 결과 `stream2clip.exe`는 매회, `stream2clip-gui.exe`는 1회 차단(2회는 실행)

## 수집

| 대상 | 검증 내용 | 미검증 |
|:---:|---|---|
| YouTube | 가정용 회선(Windows 11, yt-dlp 2026.10.26)에서 쿠키 없이 공개 아카이브 1개 수신: 방송 정보, 채팅 다시보기(44,000개, 약 10분 소요), 자동 자막 VTT, 480p 영상, `auto`로 클립 제작까지 확인. 채팅 파서는 해당 파일의 익명화 발췌본으로도 테스트 | 서버 IP에서는 봇 확인으로 차단될 수 있음(쿠키 옵션 사용) |
| YouTube, 주소만으로 클립 제작 | 동일 아카이브에서 구간 2개(158초)를 수신하여 클립 2개 제작에 1분 45초. 구간 다운로드는 HLS 형식을 우선 선택(DASH 형식은 64초 구간이 6분 이상 미완료, HLS는 13초). 앱의 하이라이트 창에서도 동일 주소로 확인: 검출 3분 12초, 클립 2개 내보내기 4분 36초(1080p 구간 2개, 88MB) | 없음 |
| CHZZK | 공개 다시보기 1개에서 채팅 983개 수신(6초), 하이라이트 검출까지 확인. 4시간 39분 다시보기에서 `auto <주소> --top 2`가 약 3분에 90초 클립 2개 제작, 다운로드한 영상은 구간 2개 11MB(480p). 앱의 하이라이트 창에서도 동일 다시보기로 확인: 검출 3초, 클립 2개 내보내기 5분 31초(1080p 구간 2개, 29MB) | 비공개, 성인 인증, 구독자 전용 다시보기 |
| SOOP | 공개 다시보기 1개에서 채팅 1,567개 수신(8초, 별풍선 포함), 하이라이트 검출, 20초 구간 다운로드 확인 | 앱의 하이라이트 창에서 SOOP 주소 실행. 비공개, 성인 인증, 구독자 전용 다시보기 |

CHZZK 구간 다운로드 실패의 원인은 ffmpeg 7.1 이후의 HLS 확장자 검사(`.m4s` 조각 거부)이며, CHZZK 구간 수신 시에만 해당 검사를 해제

## 자막 및 오디오

| 기능 | 검증 내용 | 미검증 |
|:---:|---|---|
| 자막 번역 | 예제 번역기를 로컬 Ollama(qwen2.5:7b)에 연결하여 실제 방송의 일본어 자동 자막 20초 구간을 한국어로 번역, 원문 병기 자막 클립까지 확인(약 40초). 이 모델에서는 한 줄에 영어, 중국어가 혼입된 사례 존재. 연결은 확인되었으며 품질은 모델에 좌우 | 유료 번역 서비스. Holodex 이름 초안은 API 키가 없어 가짜 응답으로만 테스트 |
| 노래 구간 검출 | 실제 노래 방송 1개(94분)에서 노래 구간 11개, 실제 게임 방송 1개(85분)에서 0개. YouTube 자동 자막의 [音楽] 표시 중 86%가 검출 구간 내 | 방송 2개의 결과에 한정 |
| 웃음소리 신호 | 실험 기능(기본값 사용 안 함). 방송 1개에서 상위 순간 이후 채팅의 웃음 반응이 평소의 2.1배(음량만 사용 시 1.9배) | 실제 웃음소리 검출 여부 |

## OBS 연동

- 환경: OBS Studio 33.0.1(obs-websocket 5.7.6, Windows 11)
- 확인 항목: 비밀번호 인증(잘못된 비밀번호, 누락된 비밀번호 거절), 리플레이 버퍼 시작 및 저장, 마지막 5초 GIF(명령줄), 마지막 3초 MP4(앱의 리플레이 저장 버튼)
- 안내 문구에 반영한 사항 2건
  - 신규 설치한 OBS는 리플레이 버퍼가 꺼진 상태. 설정의 출력 메뉴에서 사용 설정 필요
  - 장면에 소스가 없으면 OBS가 "소스 없음" 확인 창을 표시하고 버퍼를 시작하지 않음
- 미검증: OBS 28~32, 다른 PC의 OBS(원격 연결)

## 라이브 모드

- 명령줄: 실제 OBS와 실제 YouTube 라이브 채팅(분당 약 25개)으로 확인. 버퍼가 꺼진 경우 즉시 안내, 급증 2회에 35초 클립 2개를 55초 리플레이에서 잘라 저장. 이 확인에서는 수 분 내 발동하도록 임계값을 1로 하향
- 런처: 동일 환경에서 시작, 클립 저장, 중지 확인(임계값 하향 설정)
- 기본 설정 관찰: 실제 방송 1개를 30분 관찰하여 6회 발동. 이 결과에 따라 구간당 최소 메시지 수를 8로 조정([DETECTION.md](DETECTION.md#실제-방송-관찰에-따른-조정))
- 미검증: 기본 임계값에서의 클립 절단 위치와 실제 장면의 일치 여부(종료된 방송의 채팅으로만 측정). CHZZK, SOOP 라이브 채팅 직접 수신은 미구현

## YouTube 업로드

- 실제 업로드 미실시(계정과 OAuth가 필요하며 게시가 수반되는 작업)
- 요청 본문과 진행 처리는 가짜 API로 테스트(앱의 업로드 창 포함)
- 쿼터는 공식 문서 기준(2026-11 확인)
